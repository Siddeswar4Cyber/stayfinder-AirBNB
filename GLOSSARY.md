# Glossary

| Term | Meaning in this project |
|---|---|
| Assignment baseline | Features explicitly labeled Core Features (Must Have) and related required notes/deliverables in the supplied SDE Fullstack Assignment. |
| Visitor | Person using public browse/search/details without being signed in. |
| Guest | Registered user seeking/booking a stay. |
| Host | User whose host application was approved and who manages owned listings. |
| Admin | User allowed to approve/reject Host applications; no broad admin console planned. |
| Host application | Request to gain Host privileges; pending until Admin decision. |
| RBAC | Role-based access control. Backend grants actions based on authenticated role and ownership. |
| Listing/stay | Accommodation offered for a date range. |
| Availability interval | Nights occupied by a confirmed booking; proposed interval convention is check-in inclusive/check-out exclusive. |
| Mock checkout/payment | Simulated checkout used for demonstration; no real payment processor or real credential handling. |
| Match Score | Proposed rule-based score using selected preferences, equally weighted, with explanation. Not an ML model. |
| Comparison | Proposed side-by-side comparison of up to four stays. |
| Synthetic seed data | Demonstration listings, accounts, photos references, reviews, and bookings created for the app; not real marketplace records. |
| OpenRouter free router | Optional external endpoint selecting among currently available free models; not stable identity or guaranteed service. |
| Core vs extra | Assignment must-have vs user-confirmed/project-proposed feature. See `REQUIREMENTS.md`. |
